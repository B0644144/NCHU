# TREK GitHub 專案實作報告大綱

用途：10 分鐘報告 + 5 分鐘 Demo  
主軸：介紹如何使用 GitHub 上的 TREK 開源專案，實作出「岩原、神立、神樂滑雪 - 進階」旅行規劃系統  

## 內容評估

目前產出的投影片視覺完整、頁數也適合 10 分鐘報告，但敘事方向需要調整。

目前版本比較像是在介紹「TREK Lite 架構改造」，重點放在 Pure Client-Side、localStorage、Zustand、BroadcastChannel、TSP、PDF 匯出等技術亮點。這樣會讓觀眾以為報告主軸是「重寫或改造 TREK 架構」。

如果今晚的報告目標是介紹「我如何使用 GitHub 上的 TREK 專案，整理 Notion 資料並做出一個可用的旅行規劃成果」，建議把技術比重降低，改成成果導向與流程導向。

## 建議主軸

一句話主軸：

> 我使用 GitHub 上的 TREK 開源旅行規劃專案，將原本分散在 Notion 的滑雪行程、地圖點、物品清單與費用資料，整理成一個可以實際操作與展示的旅行規劃系統。

報告時可以強調三個重點：

1. 我選了一個現有的 GitHub 開源專案，而不是從零開始。
2. 我把自己的旅行資料整理進系統，讓它變成可操作的行程工具。
3. Demo 展示的是實際成果：行程、地圖、物品清單、費用與 README。

## 10 分鐘投影片建議

### Slide 1：專案標題

標題：

> 使用 TREK GitHub 專案打造滑雪旅行規劃系統

副標：

> 岩原、神立、神樂滑雪 - 進階

口白重點：

- 今天不是介紹一個從零開始寫的系統。
- 我想分享的是如何使用 GitHub 上的開源專案 TREK，整理出一個實際可用的旅行規劃工具。

### Slide 2：問題背景

標題：

> 旅行規劃資料太分散

內容重點：

- 行程在 Notion。
- 地點要另外查 Google Map。
- 物品清單和費用分散在不同頁面。
- 交通、住宿、景點混在一起，實際使用時不夠直覺。

口白重點：

- 原本資料不是沒有整理，而是還不夠「系統化」。
- 報告目標是把資料從文字紀錄變成可以操作的旅行規劃系統。

### Slide 3：為什麼選 TREK

標題：

> 為什麼使用 GitHub 上的 TREK？

內容重點：

- TREK 是開源旅行規劃系統。
- 本身支援行程、地圖、住宿、費用、打包清單。
- 比單純用 Notion 更適合做旅行管理。
- 使用現有開源專案可以把重點放在資料整理與實際應用。

口白重點：

- 我不是重新發明旅行規劃工具，而是站在現有專案上做實作。
- 這也是使用 GitHub 開源專案的價值：先理解專案，再把它變成自己的應用。

### Slide 4：我的實作流程

標題：

> 從 GitHub 專案到可用系統

建議用流程圖：


口白重點：

- 這頁是整場報告的核心。

### Slide 5：資料來源

### Slide 6：行程整理成果

標題：

> 建立 2026 日本滑雪行程

內容重點：

- 建立每日行程、住宿、交通與活動。

### Slide 7：地圖點成果

- 部分私人或不明確地點標記為約略位置。

建議畫面：

- 放地圖畫面截圖。
- 或列出幾個代表地點：神立雪場、神樂滑雪場、築地市場、雷門、Shibuya Sky。

口白重點：

- 這是最適合 demo 的功能之一。
- 觀眾可以很快理解：資料不是只放進表格，而是真的能在地圖上看。

口白重點：

- TREK 的好處是可以把這些都集中在同一個系統。

## 目前投影片建議刪減或改寫的地方

建議降低以下內容比重：

- Pure Client-Side 的零伺服器魔法。
- localStorage、Zustand、BroadcastChannel。
- TSP 演算法。
- MCP 技術細節。
- 架構改造、重寫、免後端這類敘述。

原因：

- 你這次報告想講的是「使用 GitHub 專案到實作成果」，不是深入技術架構。
- 如果 demo 現場沒有真的展示這些功能，講太多會讓觀眾期待錯誤。
- 技術細節太多會吃掉 10 分鐘報告時間，反而沒有時間講資料整理與實作流程。

建議保留但改寫的內容：

- 原本的「為什麼選 TREK Lite？」可以改成「為什麼選 TREK？」。
- 原本的「架構改造」可以改成「開源專案導入與資料整理」。
- 原本的「技術亮點」可以改成「實作成果」。
- 原本的「未來 AI/MCP」可以放到最後一頁簡短提到即可。

## 最推薦的報告定位

不要把今晚報告定位成：

> 我重寫了一套旅行規劃系統。

比較適合定位成：

> 我使用 GitHub 上的 TREK 開源專案，學習它的功能並整理自己的旅行資料，最後做出一套可以實際展示與使用的滑雪旅行規劃工作區。

這樣比較貼近目前成果，也比較容易在 10 分鐘內講清楚。
