# 岩原、神立、神樂滑雪 - 進階專案報告

報告日期：2026-06-05  
專案 Repository：[B0644144/NCHU](https://github.com/B0644144/NCHU)  
系統基礎：[TREK](https://github.com/mauriceboe/TREK)

## 一、專案摘要

本專案以開源旅行規劃系統 TREK 為基礎，將 Notion 中的日本滑雪行程資料整理、補齊並匯入到本機旅行管理系統中。行程主題為「岩原、神立、神樂滑雪 - 進階」，時間為 2026-02-26 至 2026-03-04，內容涵蓋東京、越後湯澤、岩原、神立與神樂等地。

這次專案的重點不是單純做一份靜態行程表，而是把原本分散在 Notion 裡的行程、住宿、交通、景點、滑雪活動、旅行物品檢查與費用紀錄，整理成可以在 TREK 系統中操作、查詢與展示的結構化資料。完成後，使用者可以透過網頁介面查看每日行程、地圖點、住宿安排、預訂資訊、打包清單與費用管理。

## 二、專案背景

原始行程資料主要存放在 Notion 中，內容已經包含很多有價值的資訊，但資料型態比較偏向人工閱讀，若要實際旅行中使用，仍會遇到幾個問題：

- 行程、交通、住宿、費用與物品清單分散在不同頁面。
- 部分資料需要轉成系統可以使用的日期、時間、分類與地圖座標。
- 行程中的交通移動與實際景點需要區分，避免地圖上產生不必要的標記。
- 費用與打包清單需要能被系統追蹤，而不是只停留在文字紀錄。
- 若要對外展示專案，需要有清楚的 README 與專案說明。

因此，本次專案的目標是把 Notion 內容轉換成 TREK 可用的旅行資料，並同步整理 GitHub 專案文件，讓整個專案能被展示、維護與後續擴充。

## 三、專案目標

本次專案主要完成以下目標：

1. 將 Notion 的滑雪行程完整整理進 TREK 系統。
2. 補齊每日行程、住宿、預訂資訊、備註與交通段落。
3. 將景點、雪場、住宿與餐廳建立為地圖點。
4. 針對交通移動項目，例如「桃園 >> 成田」，避免建立成景點 marker。
5. 匯入旅行物品檢查清單，保留分類與完成狀態。
6. 匯入費用記錄清單，建立預算與支出項目。
7. 確認 GitHub repository 與本機專案對應關係。
8. 將 GitHub README 替換成這次專案的說明內容。

## 四、使用技術與系統架構

本專案基於 TREK 旅行規劃工具，主要技術組成如下：

| 類別 | 使用技術 |
|---|---|
| 前端 | React、Vite、TypeScript |
| 後端 | Node.js、Express |
| 資料庫 | SQLite |
| 地圖 | Leaflet / Mapbox 相關地圖能力 |
| 即時同步 | WebSocket |
| 專案管理 | Git、GitHub |
| 資料來源 | Notion |

TREK 原本是一套自架旅行規劃系統，支援多人旅行、地圖、預算、打包清單、預訂資訊與旅行紀錄。本次專案不是從零開始開發整套系統，而是選擇以 TREK 作為基礎，將實際旅行資料整理進系統，使它成為一個可用的滑雪行程管理工具。

## 七、地圖點建立邏輯

建立地圖點時，採用以下原則：

- 景點要建立地圖點。
- 雪場要建立地圖點。
- 住宿要建立地圖點。
- 餐廳要建立地圖點。
- 主要購物或活動地點要建立地圖點。
- 單純交通移動不建立地圖點。
- 不明確或過於概念性的項目，例如「早餐自理」、「泡湯」，視情況不建立 marker。

本次已建立地圖點的代表項目包含：

- 岩原相關滑雪地點
- 神立雪場
- 神樂滑雪場
- 越後湯澤住宿
- 東京住宿
- 築地市場
- 今戶神社
- 雷門
- 澀谷相關景點
- Shibuya Sky
- 東京迪士尼
- 鎌倉
- 豪德寺
- 餐廳與購物地點

部分地點若無法取得精準地址，會以可確認的附近位置建立近似座標，並在備註中標記為約略位置，方便後續人工確認。

這讓旅行前的準備工作可以被系統追蹤，也能清楚知道哪些項目已經完成、哪些還需要補齊。

## 九、費用記錄整理

費用清單也已從 Notion 匯入 TREK 系統，共整理 62 筆支出項目。原始資料包含日幣與台幣金額，系統中依行程日與類型整理成預算項目。

整理後的費用可用於：

- 查看整體旅行預算。
- 追蹤每日支出。
- 分類住宿、交通、餐飲、滑雪與活動費用。
- 後續做分帳或預算檢討。

由於 TREK 的預算項目主要使用單一數值欄位，本次針對日幣資料使用約略匯率換算成台幣估算值，方便統一呈現總額。若後續要做正式結算，可以再加入更完整的多幣別與匯率欄位。

## 十二、專案價值

這個專案的價值在於把「旅行資料」從單純的文字紀錄，轉換成可操作的系統資料。

原本在 Notion 中，行程可以閱讀，但不一定方便查詢、分類、地圖顯示或費用追蹤。透過 TREK 系統整理後，資料變成可以被地圖、行程表、清單與預算功能使用的內容。這讓旅行規劃從靜態文件變成互動式工具。

對使用者而言，實際好處包含：

- 行程資訊集中管理。
- 地圖上可直接查看重要地點。
- 打包清單可追蹤完成狀態。
- 費用資料可做預算管理。
- 交通與景點被清楚區分。
- 專案文件可在 GitHub 上展示與維護。

## 十三、限制與後續改善

目前專案仍有一些可改善的地方：

- 部分住宿或私人地點只有約略位置，需要人工確認精準地址。

- 後續可以加入更完整的分享、分帳、離線查看與 PDF 輸出流程。
